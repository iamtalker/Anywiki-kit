# 애니위키 키트 요구 명세 (저장소 주인이 요구한 것)

주인이 대화에서 요구한 것을 그대로 모은 목록이다. 구현 여부는 오른쪽 [ ] 로 표시하고, 바뀌면 지우지 말고 "(바뀜: …)" 을 덧붙인다.

## 1. 정체성
1. 유어위키와 **분리된 별도 프로젝트**다. [x]
2. 나무위키를 위한 기능(나무위키 데이터 받기, 최신판 동기화 등 어려운 기능)은 **넣지 않는다.** [x]
3. 지금까지 만든 것(유어위키)을 포크하되 나무위키용 기능은 모두 쳐낸다. [x] (0.1)

## 2. 엔진
4. 위키 엔진을 **DokuWiki · MediaWiki · openNAMU · Markdown** 중에서 골라 쓸 수 있다. [x] (0.3)
5. 엔진이 선택되면 **그 엔진이 가진 플러그인도 설치**할 수 있다. [x] (0.4: DokuWiki 저장소 설치·켜고 끄기, MediaWiki 동봉 확장 켜고 끄기, Markdown 수식·코드 색칠)

## 3. 데이터 이동
6. **내보내기와 가져오기 모두** 네 형식(DokuWiki · MediaWiki · openNAMU · Markdown)으로 된다. [x] (0.3)
7. 키트 안에서 **데이터 형식(엔진)을 바꿀 수 있다**: 예) DokuWiki → MediaWiki, MediaWiki → openNAMU. [x] (0.3)
8. 중간에 **공용 언어**를 둔다: **마크다운을 확장**한 형식으로, 사용자는 볼 필요 없이 **백그라운드에서 통역용**으로 돈다. [x] (0.2, AWM)

## 4. 공동위키
9. 유어위키의 "상대방 ID 를 적는" 기능을 **공동위키 기능**으로 살린다. [x] (0.5)
10. 공동위키이므로 **서로가 서로의 ID 를 적어야**(양쪽 모두 등록해야) 이어진다. [x] (0.5, 창구가 회원이 아닌 ID 를 거절)

## 5. 공개
11. **일시적 주소로 공개 위키를 만드는 기능은 유지**한다. [x] (관리판 [공개하기], 리눅스 TUNNEL=on)

## 6. 일하는 방식
12. 만들면서 **README 를 쓰고, 커밋하고, 릴리스하면서 변경 이력을 관리**한다. [x] (계속. 태그 푸시는 이 환경에서 막혀 CHANGELOG 에 커밋으로 적음)
13. 주인은 일해야 하므로 **웬만해서는 AI 혼자 구현**한다. [x] (0.2~0.5)
14. (유어위키에서 이어짐) 답은 한국어로, 설정은 재시작 뒤에도 유지, 누군가 계속 관리해야 하는 서버는 기본값이 될 수 없다.

## 구현 결정 (AI 가 정함, 이유와 함께)
- 공용 언어: **AWM(애니위키 마크다운)** = GFM 마크다운 + 확장(위키 링크 `[[문서|글]]`, 틀 `{{이름|인자}}`, 각주, 접기 `<details>`,
  수식 `$…$`, 원문 보존 블록, 머리말(분류·넘겨주기)). 각 형식은 "읽기: 형식 → 공통 구조(AST)" 와 "쓰기: 공통 구조 → 형식" 만 있으면
  모든 조합(4×4)이 된다. 옮길 수 없는 문법은 원문 보존 블록으로 싸서, 같은 엔진으로 돌아갈 때는 잃지 않는다.
- Markdown 엔진: 파이썬 표준 라이브러리로 만든 **내장 엔진**(설치할 것이 없음, `.md` 파일로 저장, 역사 보관).
- DokuWiki·MediaWiki: PHP 프로그램이라 **PHP 가 필요**하다(Windows 는 휴대용 PHP 를 받고, 리눅스는 시스템 PHP).
  엔진 파일은 **Docker Hub 의 공식 이미지 층(layer)을 해시(sha256 digest)로 고정**해 받는다(계정·Docker 불필요, 받은 뒤 해시 검증).
- 공동위키: 유어위키 P2P 의 서명 ID(Ed25519)·DHT·임시 주소 창구를 재사용한다. 문서는 공용 언어로 주고받으므로
  **서로 다른 엔진끼리도** 공동위키가 된다. 양쪽이 서로의 ID 를 등록했는지는 상대가 서명한 회원 목록으로 확인한다.
- 릴리스: AI 는 GitHub 릴리스를 직접 만들 수 없어 **git 태그(v0.2 …)** 를 올리고 CHANGELOG 에 적는다. 릴리스 페이지는 주인이 태그에서 만든다.
